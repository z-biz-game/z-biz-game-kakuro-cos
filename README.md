# 加算十字 · Kakuro（零猜测交叉和推理）

> *黑格里印的两个数各管一条串：一个说横着加起来是多少，一个说竖着加起来是多少。
> 出货的每一局都先用玩家也会用的那套铅笔规则推到底过一次，唯一解再由第二套互不信任的穷举代码逐格复核。*

浏览器原生的 **Kakuro / 交叉求和**：无构建步骤、无打包器、**零美术与音频文件**——棋盘、字形、
线索对角、铅笔标记全部由 `<canvas>` 现画，音效由 WebAudio 合成，运行时依赖 **0 个**。

⚠️ **本作不是"数和"**。`z-biz-game-kakurasu-cos` 那个仓占的是 *数和 / Kakurasu*（0-1 棋盘、
行列加减筛选），本作是 *加算十字 / Kakuro*：白格里填 **1..9 且同一条 run 内不许重复**，
加起来要正好等于黑格写的和。两个游戏不是一个东西，名字也别混。

## 规则（原文）

> 这一段是 `js/render/board.js:3` 和 `js/theme.js:61` 注释里点名的"README 规则原文"。

- 盘面是方格纸，分成**黑格**和**白格**。黑格里用一条左上→右下对角线分开两个数。
- **黑格右上**那个数 = **这格下面那一竖串**白格数字之和；
  **黑格右下**那个数 = **这格右边那一横串**白格数字之和。
- 白格填 **1..9**。**同一条 run 里数字不许重复**——横着那串内部不重复，竖着那串内部也不重复，
  一个格同时受它所在的两条 run 约束。
- **一条 run** 就是被黑格切断的每一段连续白格：同一行里被黑格隔开就是两条 run，同一列同理。
- 每条 run 的和都必须**正好等于**它写的数，不多不少；一格都不许留空。
- 因此第 1 行和第 1 列整条都是黑格——每条 run 总得有人替它写和。这条不是习惯而是结构：
  `createBoard()` 在建盘时就把它当硬约束（`js/engine/kakuro.js:123`），
  并且要求**印出的和的个数恰好等于 run 的条数**（`js/engine/kakuro.js:226`）。

一条 run 是 L 格、和是 S，能填的数字组合就一只手数得过来（实测最多 12 种，出现在 C(4,20)，
见 `npm test` 的 A 节）。玩家拿铅笔在格边上写的"这格只能是 2 或 5"，就是交叉那两条 run 的
组合清单取交集——这是本作全部的推理地基。

## 怎么玩

浏览器里：点一个白格选中它，再按数字。

| 操作 | 行为 |
|---|---|
| **点白格** / **方向键** | 选中这一格（点黑格不会改变选中：黑格只是写着和） |
| **`1`…`9`** 或点数字键盘 | 落子。写数字之前引擎只拦"硬违反"：同一条 run 里重复、和超界、或者剩下怎么都凑不出这个和——并点名是哪条 run（`legalPlace`，`js/engine/kakuro.js:1054`；这条拒绝路径**没有断言**，见下面"未验证"） |
| **`N`** / 「记铅笔」 | 切铅笔模式：这一格上逐个加、逐个删候选，不写数 |
| **按候选填满铅笔** | 把引擎算出的当前候选域原样写成这格的铅笔标记（它**不计入步数**：`tools/scenarios.js:302`「候选填满本身不计步」） |
| **`H`** / 「提示」 | 说出**当前推得出的一格**和它依据哪条规则；这一步**不替你落子**，只把候选收敛，并按求助计一次 |
| **`Z`** / 「撤销」 | 退掉上一步——写数字、铅笔、擦格各算一步（`tools/scenarios.js:265`、`305`），能一路退到空盘（`tools/scenarios.js:424`「撤销能退回空盘」） |
| **`C`** / 「检查这一局」 | 只给判定，不给答案：哪条 run 撞破了、还剩几格空着 |
| **`⌫`** / 「擦这格」 | 清空这一格的墨与铅笔 |
| 「铅笔 显/藏」、「音效 开/关」 | 界面读数与合成音开关，设置一起进存档 |

内容有三层：**章节题本**（五档 × 5 局 = 25 局，构建期烘好并逐局复验）、**现抽一局**（五档任选，
入门/简单/中等现场生成；难/烧脑两档在 `TIERS` 里就写着 `live:false`，界面从烘好的 5+5 局里轮着取，
**不现场生成**——`js/engine/generate.js:307-311` 的注释说那两档现场抽要几十秒，
这个耗时我没有实测数字，所以只把"不现场生成"写进承诺）、
**今日日课**（种子只由日期决定，同一天全世界同一张盘，`js/library.js:63` 定为中等 7×7）。

```bash
npm start            # 零依赖静态服务 → http://127.0.0.1:5316
npm run dev          # 同一个端口 5316（验证台用的也是它）
npm run electron     # 桌面壳（electron/main.cjs，同一份代码，无构建）
```

## 这个仓敢承诺什么

每条后面括号里就是它的实测出处；写不出出处的话就不写在下面。

1. **零猜测**：出货的每一局都能**只用那六条规则从空盘推到底**，一次都不猜——
   25 局实测落子 632 步、划候选 1,674 次全部推完（`npm test` G 节）；这六条规则写下的
   **2,362 条结论**逐条被测试文件自带的第三套独立穷举确认（29 盘、42 个解，C 节）；
   推不完或进差法要求不符的盘在生成期就整盘丢掉（`js/engine/generate.js:223` `carveToSolvable`）。
2. **唯一解由第二套互不信任的实现逐格复核**：`js/engine/count.js` 不 import 引擎、
   自己重扫网格建 run 表、不用组合清单、不认识任何推理规则，只按行主序穷举。
   25 局里 **632 个白格、619 条 run 逐格比对零不一致**（E 节 E3/E5），而且测试把引擎的
   run 表、密集下标、片区缓存全抹掉再数一遍，穷举的结果一字不变（E6），同一份抹掉对铅笔
   路径是要出事的（E7）——两边确实各写了一遍几何。
3. **提示是推得出的下一步，不是答案**：提示走**同一个** `solve()` 产出的推导脚本，
   点名用了哪条规则、落在第几行第几列（浏览器 `hint` 场景断言文案必带坐标、
   "提示之后棋盘仍是空盘"、place 类提示把候选收敛到那个数且与解一致）。
4. **提示在玩家自己的墨与线索矛盾时不收费**：`conflict` 场景先构造出一个"合法但救不回来"的局面，
   再要求提示 `charged=false`、计数仍 0、**存档里的提示数也是 0**，并把矛盾说清楚；
   退干净之后提示才恢复收费。
5. **判胜走独立验收**：`verify()` 重新扫一遍网格、不用 `board.runs`、不读推导脚本
   （`js/engine/kakuro.js:924`）。`win` 场景要求照解填完才判胜，引擎测试再把答案手改一格、
   要求 `verify` 立刻抓到（G 节 G8）——所以"永远判胜"这类缺陷当场会红。
6. **难度是量出来的**：五档的 `band` 是**选取目标**，`npm run balance` 是门禁。
   `SAMPLES=24 npm run balance` 打出的中位数是
   **19.8 < 33.6 < 53.2 < 103.9 < 136.5**（严格递增），各档 `超预算 0/N`，
   `难` 档 `进差法：用到 4/4，不用就推不完 4/4`。

## 这个仓**不承诺**什么

这一段是上面那六句的可信度来源——反面写清楚，正面才算数。

- **不承诺"每一条线索都是承重墙"，也不承诺"线索集已是最简"。** 实测（`npm test` H 节）：
  25 局共 **619 条线索，其中 618 条可以单独抹掉而盘面仍然唯一**，1 条在 200k 节点预算内
  没数完（没数完**不许**当成"这条必要"，要下结论只能加预算重跑），被量出"非省不可"的是 **0 条**。
  原因就是出题是 solution-first：结构决定了**每条 run 恰好带一条线索**
  （`js/engine/kakuro.js:226` 在建盘时就要求"和的个数 == run 的条数"），
  雕刻每局只能抹 **0~1 条**（`maxCarves` 改的是黑格图样，不是线索，见 `js/engine/generate.js:212`）。
  实测口径写在 `js/engine/generate.js:437`（`redundantClues` 的注释）和 H 节的输出行里。
  **过约束不影响任何一条承诺**：承诺的是"唯一解在预算内证完 + 铅笔推得完 + 两套实现逐格相同"，
  从来不是"线索最少"。谁哪天要把"线索最小"写成承诺，就得让 H 节那个 618 掉到 0。
- **不承诺"任何一块 Kakuro 盘面都能被这六条规则推完"**：这六条规则**不完备**（这是取舍不是缺陷）。
  推不完的盘不出货，所以本作能出货的难度上限就是这六条规则的极限，`难` 档就是靠"不用进差法就推不完"
  这个**实测差**来定位的（`solve(board, {regions:false})` 停在半路，D 节 D12 独立复算过）。
- **不承诺 25 局之外的题本**。章节是烘好的固定 25 局；只有入门/简单/中等三档能现场无限抽。
- **不承诺穷举预算之下"唯一"之外更强的结论。** 预算用完 = 唯一解没证完 = 这一局直接拒收
  （F 节：入门档在 4 节点预算下抽满 6,000 张也**拒不出一局**；放宽到 6 节点才出货，
  并如实报出丢弃了 10 张超预算候选）。想要更多题只有一个正当办法：加预算或缩小该档盘面。
- **未验证**（跑过才有资格写，这里没跑过）：Safari / Firefox / 移动端实机——门禁只在本机
  headless Chrome（外加 runner 那种经典滚动条形态）上跑；低端机上的出题耗时；读屏与键盘无障碍。
  Pages 线上产物**已验证**：逐字节比回 HEAD 加上对着 CDN 实跑一遍闸，数字在"技术形态"节末。
- **两条"只有代码、没有断言"的缺口**（写在这里而不是藏在形容词里）：
  ① `js/store.js` 的清洗函数在**引擎测试里没有断言**（`tools/engine-test.mjs:82` 起 import 了
  `sanitize*` / `rleEncode` / `createStore` 却没用），存档形状的实测出处全部在浏览器
  `dirty-a / dirty-b / dirty-c` 与 `play / resume-*` 场景里；
  ② `legalPlace` 的**拒绝路径**同样没被断言——`conflict` 场景只把它当搜索工具用
  （`tools/scenarios.js:385` 拿它挑"合法但救不回来"的格子），没断言它拒的是什么。
  所以上面操作表里"拒绝落子并点名哪条 run"那句是**读代码得来的**（`js/ui/game.js:200-209` +
  `js/engine/kakuro.js:1050-1100`），不是实测。

## 难度是量出来的

`TIERS[]` 里读得到的四个旋钮（`js/engine/generate.js:312-383`），分数带是**先跑分位表再填进来的**：

| 档 | 盘面 | 黑格密度 | 最多雕几刀 | 进差法要求 | 选取目标 band（代码常数） | 题本 | 实测中位（balance，SAMPLES=24） |
|---|---|---|---|---|---|---|---|
| 入门 | 5×5 | 0.5 | 0 | 一次都不许用 | 10–30 | 5 局（烘好） | 19.8 |
| 简单 | 6×6 | 0.46 | 0 | 一次都不许用 | 18–50 | 5 局（烘好） | 33.6 |
| 中等 | 7×7 | 0.4 | 1 | 不管 | 30–85 | 5 局（烘好） | 53.2 |
| 难 | 8×8 | 0.36 | 2 | **不用就推不完** | 70–180 | 5 局（烘好，`live:false`） | 103.9 |
| 烧脑 | 10×10 | 0.3 | 6 | 不管 | 110–240 | 5 局（烘好，`live:false`） | 136.5 |

分数是**推导事件按规则加权后的和**（六条规则的权重是 1 / 1 / 1.6 / 2.2 / 2.6 / 5，
见 `js/engine/kakuro.js:273` 的 `Rules` 表），所以它同时反映盘有多大、候选要夹多少层。

## 六条规则（提示只会说这些）

| 规则 | 说什么 | 层级 / 权重 | 实测触发（25 局 + 4 个人工盘） |
|---|---|---|---|
| 组合清单 | 这条 run 活下来的组合里，这格只剩这几个数 | 1 / 1 | 467 |
| 只剩一个 | 被两条 run 的清单夹到只剩一个数，写下 | 1 / 1 | 13 |
| 唯一组合 | 这条 run 只剩一种组合，整套数字把格子框住了 | 2 / 1.6 | 1,032 |
| 必含之数 | 每种组合都含 7，而这条 run 只有一格放得下 7 | 2 / 2.2 | 595 |
| 占位排他 | 把数字摆回空格试，摆不下的那个候选划掉（二部图匹配） | 2 / 2.6 | 215 |
| 进差法 | 把几行看成一片：整片横向和 − 完整落在片内的纵向和 = 伸出去那几格的和 | 3 / 5 | 40 |

六条都不含猜测：每一步写下的候选消去/落子对盘面的**每一个解**都成立（论证见 `DESIGN.md` §3、§5），
所以"铅笔推得完 ⟹ 解唯一"。反方向不成立——有些唯一解的盘这六条推不完，那正是生成器要丢掉的东西。

## 跑测试：五条命令各自证明什么

```bash
npm run check        # 逐文件 node --check + 入口断言（index.html 里有 <canvas>、main.js 挂 window.kakuro）
npm test             # 引擎断言 144 通过 / 0 失败，分节 A–H（每节都打实测数字，不是只打 ok）
npm run bake         # 构建期烘 25 局进 js/data/levels.js（连答案 ink 与每一局的读数）
npm run bake -- --check   # 复验：✓ 25 局复验一致；五档各「超预算 0 局」，穷举节点最多 18/76/285/4191/9625
SAMPLES=24 npm run balance # 难度尺：对账 405 格 0 处不一致、五档中位数递增、各档超预算 0/N，不成立就 exit 1
npm run verify       # 真实 headless Chrome：14 个场景 / 231 条断言 / 0 失败（HTTP 5316、CDP 9366）
```

- `npm test` 的八节：A 组合数学（405 个合式 `(L,S)` 的 DP 表与穷举逐格相等）｜B 哨兵值｜
  C 铅笔规则可靠性（2,362 条结论逐条被独立穷举确认）｜D 进差法（40 条事件、14 种片区说法）｜
  E 两套实现逐格一致｜F 超预算 ≠ 唯一｜G 铅笔推得完｜H 冗余线索**实测**。
- `npm run verify` 的场景：`first play hint conflict win resume-a resume-b resume-c resume-d
  dirty-a dirty-b dirty-c touch geom`。断言读的是 **DOM 几何与画布像素**（黑格哪个象限点亮、
  墨色数字像素、触摸目标 ≥44px、5×5 与 10×10 的几何对拍），不读内部标志位。
  `verify.sh` 有 pre-flight：先 `curl` 首页、`grep 加算十字`，证明 5316 上服务的是本作。
- 这套闸在**三种形态**下各自跑过，都是 14 场景 231 条 0 失败（2026-09-28 本机实测）：
  ① 根形态 `npm run verify`（`http://127.0.0.1:5316/`，`server.cjs` 把仓库当文档根）；
  ② Pages 的 `/<repo>/` 前缀形态——把仓库软链进一个父目录、用 `python3 -m http.server` 服务那个
  父目录，`BASE_URL=http://127.0.0.1:<port>/z-biz-game-kakuro-cos/`（CI 的 browser job 就是这么起的，
  本地起得来，不再只能靠线上复验）；
  ③ 在 ② 上再换 runner 那种**经典 15px 滚动条**：`CHROME_EXTRA_FLAGS=--disable-features=OverlayScrollbar,OverlayScrollbars,FlushOverlayScrollbars`。
  前缀形态不是凑对称：根形态的服务器分不出"斜杠开头的 import"和"相对 import"，同组织的 ulam
  就在 Pages 前缀下丢过一整段根本没跑的断言、本机却全绿。形态③换的是**平台形状**：本机默认是
  不占位的 overlay 滚动条，runner 上滚动条要从同一列里拿走 15px，只有 ③ 才会暴露"宽度由高度
  决定"那一类布局。已部署站点另算一条口径（`BASE_URL=https://z-biz-game.github.io/z-biz-game-kakuro-cos/ npm run verify`），
  每次上线之后复跑，数字记在本节末。
- **可选诊断**：`REDUNDANT=1 npm run bake -- --check` 或 `REDUNDANT=1 npm run balance` 会逐局打
  "可省线索 X/Y 条"。它**只打数、不 fail**，理由写在 `tools/balance.mjs:232-236`：
  可省不是违规（"线索最小"从来不是承诺），真正会 fail 的只有 `unproven`——那是"这次测量没做完"，
  而不是"这条线索必要"；要下结论只能加 `REDUNDANT_NODES` 重跑。
- CI（`.github/workflows/ci.yml`）跑 check / bake --check / balance(SAMPLES=24) / 引擎测试 / 入口文件，
  **不 `npm install`**：零运行时依赖、零构建步骤，装依赖只会换来网络抖动。
  浏览器门禁也进 CI：`browser` job 把 `npm run verify` 那 14 个场景跑两遍——root 形态（`server.cjs` 把仓库当文档根）
  与 Pages 真实形态（仓库挂在 `/<repo>/` 一段下）。第二遍不是凑对称：根形态的服务器分不出
  "斜杠开头的 import"和"相对 import"，同组织的 ulam 就在 Pages 前缀下丢过一整段根本没跑的断言，
  本机却全绿。`node-version: 22` 是被 `tools/playtest.cjs` 钉的——它用 22+ 才有的全局
  `WebSocket`/`fetch`，在 20 上第一条 attach 就死。

## 技术形态

- **零运行时依赖、零构建步骤**：纯 ES Module + 一块 `<canvas>` + WebAudio 合成音（`js/audio/synth.js`）。
  `devDependencies` 只有 `electron`，浏览器代码里没有一行 import 它。
- **零美术与音频文件**：棋盘、对角分割线、数字（等宽 `SF Mono`）、铅笔 3×3 标记、favicon
  （`index.html:10` 的 data URI，否则 Pages 会 404）全部代码现画。
- **视觉刻度落在代码里**：间距 20/16/12/8、圆角 20/12/8/6、最小触摸目标 44×44、
  阴影只有 0.1/0.2/0.3 三层透明黑（`js/theme.js:20-52` + `css/game.css:5`）。
- **存档一个键** `kakuro.save.v1`：盘本身不进存储（生成器确定性），墨水走 RLE、
  铅笔走"每格 2 字节小端 + RLE"；读进来每个字段都过 `sanitize*`，脏数据吞得下、

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高。
- **钉住两个数**：`EXPECT_CHECKS=37`（R 段实际检查的路径条数）与 `EXPECT_ROWS=55`
  （这一次跑的断言条数）。没改页面却掉了，说明解析断了；删掉一张图标会同时少一条 R10 与那张的
  P1/P2，所以两个数一起钉，rows 能漂就是闸在缩水的信号。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸），要求每一刀都让闸**点名**变红；X10 是阴性对照——往入口 JS 追加一行只写在注释里
的假路径，闸必须仍然绿、条数仍然 `37`、rows 仍然 `55`。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑，所以页面改了、仓与仓不同，台架跟着走。

`npm run deploy-set` 与 `npm run deploy-set:selftest` 是同两条命令的本地入口；把它们接进本仓
那条浏览器 one-shot（`tools/verify.sh`）还欠着——那道脚本的腿名单与条数钉是每个仓自己的形状。
